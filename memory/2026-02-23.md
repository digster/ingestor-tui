# 2026-02-23 — Ingestor TUI Implementation

## Summary

Built the complete Textual TUI for the Gmail Ingestor pipeline from scratch.

## What was done

1. **Project scaffold**: `pyproject.toml` with path dep on `gmail-ingestor` via `[tool.uv.sources]`, `.gitignore`, `.python-version` (3.12), directory structure under `src/ingestor_tui/`.

2. **`db_reader.py`**: Read-only SQLite access with `count_by_status()`, `last_run()`, `get_recent_messages()`, `total_messages()`. Uses short-lived connections with `PRAGMA query_only = ON`.

3. **Widgets**:
   - `log_panel.py`: `LogPanelWidget` with `RichLog` + `TUILogHandler` that pipes `gmail_ingestor.*` logs via `call_from_thread()`.
   - `dashboard.py`: `DashboardWidget` with `StatusCard` metrics (pending/fetched/converted/failed/total), last run info, config display. Auto-refreshes every 5s.
   - `operations.py`: `OperationsWidget` with 5 pipeline buttons, 5 parameter inputs, `ProgressBar` + stage label.
   - `labels.py`: `LabelsWidget` with `DataTable` for Gmail labels.

4. **`app.py`**: `IngestorApp` with `TabbedContent`, keybindings (d/o/l/g/q), `@work(thread=True, exclusive=True)` workers for pipeline ops, lazy `EmailIngestor` creation, `on_progress` callback wiring. CLI entry point with `--project-dir` arg.

5. **Tests**: 14 tests (4 app smoke tests + 10 DB reader unit tests), all passing.

6. **Documentation**: `README.md`, `ARCHITECTURE.md`, `PROMPT.md`.

## Issues encountered

- Hatchling required `tool.hatch.metadata.allow-direct-references = true` for path dependencies. Switched to `[tool.uv.sources]` instead.
- Textual 8.0 has a method `_render` on widgets internally — naming our `StatusCard._render()` method caused `AttributeError: 'str' object has no attribute 'render_strips'`. Renamed to `_format_content()`.
- Widget `__init__` methods need to pass `**kwargs` through to `super().__init__()` to support Textual's `id` parameter.

# Session 2 — TUI UX Improvements

## Summary

Implemented 7 UX improvements to the Gmail Ingestor TUI.

## What was done

1. **Fix params grid visibility**: Changed `grid-size: 2 3` → `grid-size: 2 5` in `operations.py` so all 5 input fields are visible.

2. **Reorder tabs**: Dashboard → Labels → Operations → Log. Bindings reordered to match (d, l, o, g, q).

3. **Labels search/filter**: Added `Input` field (`#labels-filter`) above the DataTable. Stores full labels in `self._all_labels`, filters on `Input.Changed` matching name or ID case-insensitively.

4. **Confirmation dialog**: New `ConfirmDialog(ModalScreen[bool])` in `widgets/confirm_dialog.py`. `on_button_pressed` is now async, uses `push_screen_wait()` before dispatching operations. Labels refresh and log clear skip confirmation.

5. **Multi-label support**: `_parse_labels()` splits comma-separated label input. `full_fetch` and `discover` iterate over parsed labels. Other operations don't use label_id.

6. **Stop button**: Added `Button("Stop", id="btn-stop", variant="error", disabled=True)`. Toggled inversely via `set_running()`. `_cancel_operation()` finds running pipeline worker and calls `worker.cancel()`. Worker checks `is_cancelled` between label iterations.

7. **Editable project directory**: Dashboard has `Input(#input-project-dir)` + `Button(#btn-apply-project-dir)`. On Apply: validates directory, `os.chdir()`, resets `_ingestor = None`, reloads settings. Disabled while operation running.

# Session 3 — Fix ConfirmDialog Crash

## Summary

Fixed `NoActiveWorker: push_screen must be run from a worker when wait_for_dismiss is True` crash when clicking operation buttons in the Operations tab.

## Changes

- **`src/ingestor_tui/app.py`**: Replaced `await self.push_screen_wait(ConfirmDialog(...))` with `self.push_screen(ConfirmDialog(...), callback=...)` in `on_button_pressed`. The callback pattern is the correct approach for showing modal dialogs from Textual message handlers, which run on the main thread (not a worker thread).

## Key Detail

Used `op=operation` default argument in the lambda to avoid the Python late-binding closure issue where all callbacks would reference the same variable.
