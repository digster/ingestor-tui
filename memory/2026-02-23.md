# 2026-02-23 — Ingestor TUI Implementation

## Summary

Built the complete Textual TUI for the Gmail Ingestor pipeline from scratch.

## What was done

1. **Project scaffold**: `pyproject.toml` with path dep on `gmail-ingestor` via `[tool.uv.sources]`, `.gitignore`, `.python-version` (3.12), directory structure under `src/ingestor_tui/`.

2. **`db_reader.py`**: Read-only SQLite access with `count_by_status()`, `last_run()`, `get_recent_messages()`, `total_messages()`. Uses short-lived connections with `PRAGMA query_only = ON`.

3. **Widgets**:
   - `log_panel.py`: `LogPanelWidget` with `RichLog` + `TUILogHandler` that pipes `gmail_ingestor.*` logs via `call_from_thread()`.
   - `dashboard.py`: `DashboardWidget` with `StatusCard` metrics (pending/fetched/converted/failed/total), last run info, config display. Auto-refreshes every 5s.
   - `operations.py`: `OperationsWidget` with 5 pipeline buttons, 5 parameter inputs, `ProgressBar` + stage label.
   - `labels.py`: `LabelsWidget` with `DataTable` for Gmail labels.

4. **`app.py`**: `IngestorApp` with `TabbedContent`, keybindings (d/o/l/g/q), `@work(thread=True, exclusive=True)` workers for pipeline ops, lazy `EmailIngestor` creation, `on_progress` callback wiring. CLI entry point with `--project-dir` arg.

5. **Tests**: 14 tests (4 app smoke tests + 10 DB reader unit tests), all passing.

6. **Documentation**: `README.md`, `ARCHITECTURE.md`, `PROMPT.md`.

## Issues encountered

- Hatchling required `tool.hatch.metadata.allow-direct-references = true` for path dependencies. Switched to `[tool.uv.sources]` instead.
- Textual 8.0 has a method `_render` on widgets internally — naming our `StatusCard._render()` method caused `AttributeError: 'str' object has no attribute 'render_strips'`. Renamed to `_format_content()`.
- Widget `__init__` methods need to pass `**kwargs` through to `super().__init__()` to support Textual's `id` parameter.
