# 2026-09-12 — Multi-source backfill mappings

Two pieces of work: adding a mapping for `Neel Chhabra`, and then the schema change that
mapping turned out to need.

## Part 1 — the mapping, and what it exposed

Added `Neel Chhabra` (`Label_1703214449706674033`) → `https://resight.substack.com/archive`.
`mode: "json"` for the usual Substack reason: static HTML shows 9 entries, two of which are
the `/podcast` and `/notes` tabs rather than posts, and the rest is client-rendered.
`title_selector` is `h1.post-title`, not the `h1` used for Joan Westenberg — this
publication renders two `h1`s and the first is the masthead. Dead code in `json` mode
(`extractor.py:195` is `title = ref.title or _extract_title(...)`) but not worth leaving
wrong. Selectors verified with lxml/cssselect, the project's parser, not bs4.

Then the sender timeline showed the real problem:

| Sender | Range | Count |
|---|---|---|
| `neelchhabra@substack.com` ("Neel's Newsletter") | 2025-12-18 → 2026-05-09 | 20 |
| `resight@substack.com` ("Resight") | 2026-08-22 → 2026-09-10 | 4 |

The publication rebranded and **the back catalogue did not move**.
`neelchhabra.substack.com` still serves 23 posts; `resight.substack.com` starts at
2026-07-20 with 7. Joan Westenberg set the wrong expectation — her Substack import pulled
the whole history into the new home, so one `archive_url` covered everything. Luck, not the
rule.

Nothing in the scan flags this. `7 listed, 3 already held, 4 missing` with three exact
normalised-title hits looks entirely healthy; the matcher even confirms the `label_id` is
right. Every check in the skill's step 5 passes while 23 posts sit unvisited.

## Part 2 — `ArchiveSource`

A label now holds **one or more** archives.

- **`ArchiveSource`** (`mappings.py`): `archive_url`, `listing`, `article`, plus per-source
  `sender`, `name` and `notes`. `BackfillMapping.sources` is a non-empty tuple.
- **Both shapes accepted.** A `sources` list, or the single-archive shorthand inline on the
  mapping, normalised to a one-element tuple so everything downstream sees one shape.
  Setting both is a validation error — which archive is primary would be ambiguous.
  `archive_url` / `listing` / `article` survive as properties delegating to `sources[0]`,
  which is why all 235 pre-existing tests passed untouched.
- **`sender` is per source, resolved at parse time** with the mapping-level value as
  fallback. Not cosmetic: the pre-rebrand posts must carry `neelchhabra@substack.com` in
  their `from:`, since that is where those emails came from.
- **`ArticleRef.source_index`** tags each ref with its archive, so the runner extracts with
  the right selectors and attributes to the right sender. `source_at()` clamps out-of-range
  indexes to the primary rather than raising — an index can outlive a mapping edit.
- **Dedup spans sources on canonical URL *and* normalised title.** The title half is the
  subtle one: where a migration imported the back catalogue, both archives carry the post at
  different URLs, and different URLs mint different `web-` IDs, so URL-only dedup writes it
  twice. First source wins, hence `sources[0]` = canonical.
- **A discarded duplicate still counts as page progress.** Otherwise a fully-overlapping
  archive looks like "no new URLs", the walk ends on page 1, and everything after it is
  hidden — the same silent-truncation failure this subsystem already exists to prevent.
- **One dead archive no longer costs the others**; a single-source mapping still propagates
  its error, and all-sources-failed raises.

Also fixed while implementing: in the legacy shape the lone source inherited the
mapping-level `notes`, so `ingestor-backfill list` printed the same prose twice.
