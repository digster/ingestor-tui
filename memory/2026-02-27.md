# 2026-02-27 — Save and Load Label Presets

## Changes

- **`preset_store.py`** (new): JSON persistence class with `list_presets`, `save_preset`, `delete_preset`, `get_preset`. Stores at `~/.config/ingestor-tui/label_presets.json`. Auto-creates directory on first save.
- **`widgets/preset_name_dialog.py`** (new): `ModalScreen[str]` dialog for entering preset name. Follows `ConfirmDialog` pattern. Returns name string or empty string on cancel. Auto-focuses input, supports Enter to submit.
- **`widgets/operations.py`**: Added preset row between "Parameters" title and params-grid. `Select` dropdown + Load/Save/Del buttons. `__init__` accepts optional `PresetStore` for DI in tests. `on_mount` populates Select. All button handlers use `event.stop()` for encapsulation. `set_running` skips preset buttons (always enabled).
- **`tests/test_preset_store.py`** (new): 8 unit tests — empty list, save/get, list after save, overwrite, delete, delete missing, get missing, auto-create directory.
- **`tests/test_app.py`**: 4 new integration tests — preset widgets exist, load populates input, save empty warns, delete no selection warns.
- **ARCHITECTURE.md**: Updated component hierarchy (Select + Button x3, PresetNameDialog), key design decisions, key files table.
- **README.md**: Added label presets to Operations feature description.

## Key Decisions

- User-level config (`~/.config/`) not project-specific, so presets work across different project directories.
- `PresetStore` injected via constructor for test isolation (tests use `tmp_path`).
- `event.stop()` on preset button presses keeps all logic in `OperationsWidget` — zero changes to `app.py`.
- Preset buttons stay enabled during pipeline operations (`set_running` skips them).

## Fix: `NoActiveWorker` crash on preset Save/Delete

- **Root cause:** `_handle_save` and `_handle_delete` called `push_screen_wait()` which requires a Textual worker context, but were called with `await` from `on_button_pressed` (a message handler on the main thread).
- **Fix:** Decorated both methods with `@work` (imported as `from textual import work`, NOT `from textual.work`), made `on_button_pressed` non-async, and removed `await` from the calls.
- **Tests:** Updated `test_app.py` to call `_handle_save()` / `_handle_delete()` without `await` (they now return `Worker` objects, not coroutines).
- **LEARNINGS.md:** Fixed the import path from `from textual.work import work` to `from textual import work`.

## Fix: Vertical labels in Operations Parameters grid

- **Root cause:** `Vertical` container enforces `layout: vertical` at the widget level, overriding the `layout: grid` CSS rule on `.params-grid`.
- **Fix:** Added `Grid` to imports from `textual.containers` and replaced `Vertical(classes="params-grid")` with `Grid(classes="params-grid")`. The existing CSS (`grid-size: 2 5`, `grid-columns: 12 1fr`) now takes effect correctly.

# 2026-02-27 — Accommodate gmail-ingestor Rate Limiting & Label Persistence

## Changes

- **`app.py`**: Added `RateLimitError` import from `gmail_ingestor.core.exceptions`.
- **`app.py`** (on_mount + _apply_project_dir): Added 6 new rate-limiting settings to `show_config()`: `max_retries`, `initial_backoff_seconds`, `max_backoff_seconds`, `inter_batch_delay_seconds`, `inter_page_delay_seconds`, `num_retries`.
- **`app.py`** (_do_operation): Added specific `except RateLimitError` block before the generic `except Exception`. Provides user-friendly message suggesting to wait or adjust rate-limit settings in `.env`.

## Key Decisions

- `RateLimitError` catch placed before generic `Exception` so Python matches it first.
- New DB tables (`labels`, `message_labels`) from gmail-ingestor are internal to the library — TUI's `DBReader` only queries `messages` and `fetch_runs`, no TUI changes needed.
- No changes needed for multi-label support or pagination — already implemented.
