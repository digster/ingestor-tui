# 2026-09-02 — Backfilled articles render like ingested ones

## Problem

Backfilled Joan Westenberg articles (everything after 2026-06-06) looked wrong on
`newsletters-web`: full-bleed images, edge-to-edge text, stray icon glyphs, while ingested
emails in the same list rendered correctly.

The original report assumed `../output/markdown/*.md` held HTML from trafilatura and that
`ingestor-tools` converted it. Neither is true, and checking that changed the fix:

* `MarkdownConverter._convert_body` calls `trafilatura.extract(..., output_format="txt")`.
  Zero of the 17,132 files in `../output/markdown` contain a `<p>` tag. Ingested and
  backfilled `.md` bodies were both plain text and already matched.
* `ingestor-tools` converts nothing — it copies the `.md` and `../output/raw/{id}.html`
  verbatim into `../newsletters/<label>/<id>/`.

## Root cause

**The rendered artifact is the raw HTML, not the markdown.** `build_site.py:452-504` picks
`sorted(glob("*.html"))[0]` as the article body and uses the `.md` only for front-matter
metadata; `view.html:31` loads it in `<iframe sandbox="allow-same-origin">` and
`style.css:720` gives that frame only a white background.

Backfill reused gmail-ingestor's writers faithfully — and so matched the one file nobody
renders. Underneath: an email inlines all its styling because mail clients strip external
stylesheets, so it is self-describing; a scraped page keeps its styling on the publisher's
CDN, so storing the content subtree kept the styling *reference* and lost the styling.

## Changes

* `backfill/extractor.py` — `ARTICLE_PAGE_CSS` (mirrors `EMAIL_PAGE_CSS` in
  `newsletters-web/scripts/build_site.py`), inlined by `_wrap_document` into a complete
  document with viewport, `<title>` and a `.email-body` wrapper. Chrome stripping extended to
  `button`, `[role=button]` and form controls; `_remove_keeping_tail` preserves the text that
  followed a removed node (the old `_strip_noise` ate it); `_drop_empty_containers` removes
  wrappers left holding nothing. No `<h1>` in the body — `app.js` builds list previews from
  `<body>` text. A footer note on paywalled posts, which is safe because previews truncate
  from the start.
* `backfill/mappings.py` — `ArticleConfig.strip_selectors` per-publication override.
* `backfill/store.py` — `record_article`'s upsert no longer downgrades `done`; new
  `articles_for_label` / `delete_articles`.
* `backfill/prune.py` + `prune` subcommand — clears all four locations. Needed because
  `ingestor-tools`' `organize()` only copies and skips existing paths, so a rewritten
  `../output` file never reaches the site.
* Tests: new `test_backfill_extractor.py` (19, moved out of `test_backfill_writer.py` and
  extended) and `test_backfill_prune.py` (12); store and mappings tests extended. 235 pass.

## Bug found while implementing

`classify` reports an already-backfilled URL as `have`; the runner records every classified
entry; `record_article` did `status = excluded.status`. So a second scan downgraded `done` to
`have`, discarding the file paths — the article then churned done → have → discovered → done,
and `prune` could not find its files. Two articles were already in that state. Fixed at the
storage layer (`CASE WHEN ... status = 'done'`), and `prune` now treats files on disk as
authoritative over status so existing damage self-heals.

## Migration

Pruned 85 articles, re-ran, recovered 1 HTTP 429 with `--delay 3`. Two articles needed
restoring from a pre-migration backup: the publisher paywalled one between runs (12,318 →
199 chars) and the archive listing stopped returning the other. Verified against the backup:
**89 articles, no content regressions, nothing missing.** 63 are subscriber-only previews.
Organizer + `build_site.py` re-run; checked in the real viewer iframe and the list previews.

Note for next time: recovering a file into `../output` is not enough — delete the
`../newsletters/<label>/<id>/` directory too, or the organizer skips it.
