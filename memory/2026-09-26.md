## The bug

Paging the endpoint by hand, `limit=50` returned 23 items at `offset=0` and 35 at
`offset=50` — 58 of 85. Substack's `/api/v1/archive` caps `offset=0` at **23 posts for any
`limit`**, and returns the full `limit` at every other offset (checked on all four
publications in use). `listing._page_urls` strode by `page_size`, so posts 23–49 were
never requested. No error, and a non-round total that looked complete.

It had been silently costing the existing mappings too:

| Label | Before | After |
|---|---|---|
| Dharmesh Ba | 58 listed / 56 missing | 85 / 83 |
| Joan Westenberg | 119 / 9 | 145 / 28 — all of July 2026 was in the gap |
| Neel Chhabra | 30 / **0** | 44 / 14 — pre-rebrand archive is 37 posts, not 23 |

The 2026-09-12 note that Neel's label was "complete" was wrong because of this.

**Fix:** `_read_json` now runs its own offset loop and advances by `len(items)` (raw count,
pre-dedup). Page/none pagination and all HTML modes are unchanged — HTML item counts are
selector matches, not server counts. Item-array extraction moved into `_json_items`.

**Why the tests missed it:** fixtures mapped literal URLs to responses and could describe
an impossible server. The old `test_json_short_page_does_not_stop_pagination` encoded the
bug — `offset=0` → 1 item, `offset=2` → items 2–3. Added `FakeOffsetApi`, which slices
one fixed catalogue, plus 3 tests (gap reproduction with exact request sequence, non-zero
`start`, page-type unaffected). Terminator URLs in runner / multi-source / listing
fixtures moved from `offset=page_size` to `offset=<items received>`.

261 tests pass (3 new). Touched files ruff-clean.

# 2026-09-26 — Substack embeds survive markdown conversion

Found while spot-checking the Nabeel Qureshi mapping: "Ted Mabrey's essay … is good:"
followed by nothing. The card was in the raw HTML; trafilatura dropped it from the `.md`.

## Scope (measured over all 222 backfilled raw HTML files)

| Component | Count | Lost from markdown? | Handling |
|---|---|---|---|
| `DigestPostEmbed` | 46 in 13 files | yes — every India Notes "here are my editions" list | replaced: `Embedded post: [title](url) — authors · date` |
| `EmbeddedPostToDOM` | 3 in 2 files | yes | replaced: link line + quoted excerpt |
| `EmbeddedPublicationToDOMWithSubscribe` | 1 | yes | replaced: `Embedded publication: [name](url) — tagline · by author` |
| `Youtube2ToDOM` | 3 | yes (iframe, no text) | iframe kept, `Embedded media: [Watch on YouTube](…&t=…)` added |
| Instagram `data:` iframe | 1 | yes | iframe kept, permalink from `data-instgrm-permalink`, utm stripped |
| `ButtonCreateButton`, `CaptionedButtonToDOM` | 120 | yes — correctly | Share / Leave a comment / Subscribe chrome; left alone |
| `MentionUser`, `FootnoteToDOM`, `Image2ToDOM` | — | no | untouched |

No tweet embeds exist in the corpus. The `missing link attribute: tweeted` warning is a
different bug: trafilatura strips link targets inside `<blockquote>` (a quoted tweet in a
Palantir footnote). General converter behaviour, affects ingested emails too, not fixed.

## Design

New `backfill/embeds.py`, called from `extractor._extract_content` before `_strip_noise`,
so the stored HTML and the markdown get the same markup (the raw card was an unstyled blob
of underlined link text without Substack's CSS anyway). Three trafilatura rules shape the
output — no classes, no links in quotes, a 15+ char label on every link line; see
LEARNINGS "trafilatura drops embed cards". The first attempt used a `<blockquote>` and a bare
`<p><a>` and lost the URL and the YouTube line respectively — the label is load-bearing.
