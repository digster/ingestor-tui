# 2026-03-14 — Show Running Command Above Log Output

## Changes

### Session 1 — Add command label
- **`widgets/log_panel.py`**: Added `Static("No command running", id="command-label")` between the section title and `RichLog`. CSS uses `$text-muted` when idle, `$accent` + bold when `.active` class is present. Added `set_command(command)` and `clear_command()` methods that update content and toggle the `.active` class.
- **`app.py`**: `_run_operation()` calls `log_panel.set_command(operation)` before switching to Log tab. `_do_operation()` finally block calls `log_panel.clear_command()` via `call_from_thread`.
- **`tests/test_app.py`**: 3 new tests — command label widget exists with idle text, `set_command()` updates text + adds active class, `clear_command()` resets to idle state.
- **`ARCHITECTURE.md`**: Updated LogPanelWidget component hierarchy to include the command label.

### Session 2 — Persist command name after operation completes
- **`widgets/log_panel.py`**: Added `_current_command` field to track the running command name. Added `complete_command(status)` method that shows `"{status}: {command}"` and swaps CSS class to `.completed` (success color) or `.error` (error color for Failed/Cancelled). Added `.completed` and `.error` CSS classes. `set_command()` now also cleans up prior completion classes. `clear_command()` resets all classes and `_current_command`.
- **`app.py`**: Removed `clear_command()` from the `finally` block of `_do_operation()`. Replaced with status-specific `complete_command()` calls: success → "Completed", cancellation → "Cancelled", RateLimitError/Exception → "Failed".
- **`tests/test_app.py`**: Replaced `test_clear_command_resets_label` with 4 tests: `complete_command()` shows completed state, `complete_command("Failed")` shows error state, `complete_command("Cancelled")` shows error state, `clear_command()` still resets to idle (for Clear button use).

### Session 3 — Show CLI command in log panel label
- **`app.py`**: Added `_OPERATION_CLI_COMMANDS` dict (maps TUI operation names to CLI subcommands), `_OPERATION_CLI_FLAGS` dict (which flags each operation supports), `_PARAM_TO_FLAG` dict (param keys to CLI flag names), and `_build_cli_command()` helper that builds a full CLI command string from operation + params. Updated `_run_operation()` to call `ops.get_params()` and `_build_cli_command()` before passing the CLI string to `set_command()`.
- **`tests/test_app.py`**: Updated 4 existing command label tests to use CLI-format command strings. Added 11 unit tests for `_build_cli_command()` covering all 5 operations, None params skipped, offset=0 skipped, full_sync flag, quoted values with spaces/commas.

### Session 4 — Fix long command truncation on Log panel
- **`widgets/log_panel.py`**: Changed `#command-label` CSS from `height: 1` to `height: auto` so long CLI commands wrap to multiple lines instead of being clipped. The `RichLog` below uses `height: 1fr` and absorbs remaining space, keeping layout balanced.

## Notes
- Textual's `Static` widget stores content in name-mangled `_Static__content` — tests use `str(label._Static__content)` to read it.
- `set_command` is called on the main thread (from `_run_operation`), but `complete_command` must use `call_from_thread` since `_do_operation` runs in a `@work(thread=True)` worker.
- `_build_cli_command()` is a module-level function (not a method) since it's pure logic with no app state dependency — makes it easy to unit test without needing to spin up the Textual app.
